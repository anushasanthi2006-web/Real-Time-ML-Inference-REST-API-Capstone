# Real-Time ML Inference REST API & Capstone

A containerized machine-learning inference service built with FastAPI. It loads a trained Random Forest pipeline and exposes a JSON `/predict` endpoint that returns an Iris flower species prediction and class probabilities.

**Dataset note:** This is a reproducible demo using scikit-learn's built-in Iris dataset. Replace the demo artifact and input schema if your course requires your own previously trained champion model.

## Install and train

Python 3.11 is recommended.

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python train.py
```

## Run API

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Open `http://127.0.0.1:8000/docs` for Swagger UI, or `http://127.0.0.1:8000/health` for the health check.

## Prediction endpoint

**POST `/predict`**

Example JSON request:

```json
{
  "sepal_length": 5.1,
  "sepal_width": 3.5,
  "petal_length": 1.4,
  "petal_width": 0.2
}
```

The response contains the predicted class, probabilities for all three classes, confidence, and model version. Probability values are generated by the model and may vary slightly by dependency version.

## Tests

```bash
pytest -v
```

Tests cover health, successful prediction, probability output, missing fields, invalid ranges, and non-numeric values.

## Docker

```bash
docker build -t realtime-ml-inference:1.0.0 .
docker run --rm -p 8000:8000 realtime-ml-inference:1.0.0
```

Then open `http://localhost:8000/docs`.

## API contract

| Route | Method | Purpose |
|---|---|---|
| `/` | GET | Service information |
| `/health` | GET | Service/model health |
| `/predict` | POST | Prediction and class probabilities |

Malformed or invalid input returns HTTP 422. Unexpected inference errors return HTTP 500.

## Architecture

```text
Client -> FastAPI /predict -> Pydantic validation
       -> Feature preparation -> Loaded ML pipeline
       -> Predicted class + probabilities -> JSON response

Docker packages the API, dependencies, and trained model artifact.
```

## Production considerations

The model is loaded once when the service starts. Dependencies are pinned, input validation is enabled, tests are provided, and a health endpoint supports monitoring. A real deployment should additionally configure HTTPS, authentication, structured logging, rate limiting, monitoring, and model/data version tracking.
